Build order

Seven steps, in order. Tick tasks as you go; ticks are saved in this browser only. "Copy as checklist" gives you Markdown to paste into an issue.

Profile status rules

people.status moves only along these paths. Reject anything else with 409. The public page reads profiles, and only while the status is approved.

invited→ registered→ draft→ submitted→ approved
  • invited → registered: Clerk sign-up, then POST /api/session/sync.
  • registered → draft: the first draft save.
  • draft → submitted: submit, validated on the server.
  • submitted → approved or submitted → changes_requested: the owner's decision.
  • changes_requested → submitted and approved → submitted: the Gigster edits and resubmits.
  • Undo (latest decision, short window): approved or changes_requested → submitted.

Endpoints

One route per DataSource method. Route names are a proposal. Never trust an email, role or person id from a request body: read them from the verified token. No token → 401; owner route as a Gigster → 403.

Done when

  • The live preview runs invite → join → build → submit → approve → /p/slug against the Worker, with real emails.
  • Owner routes return 403 for a Gigster and 401 without a token.
  • Transitions outside the status rules return 409.
  • pnpm check still passes on the sample store. It is the UI's regression suite.
  • No secret in the built out/ folder.
