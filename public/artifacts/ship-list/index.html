How to leave them out. The production site should include only the "Make live" routes. Either deploy from a route allowlist, or we add a production build that drops app/workspace, app/studio, app/preview, app/emails and public/artifacts. Tell us which you prefer.

Sample-data controls hide themselves once the data source is the live API (no demo block). Nothing else in the "Make live" pages needs changing.

Order of work

The same order as the handoff, here as the milestones that let each group go live.

  1. Worker, Clerk and the API clientToken check and owner role on every request; write lib/data/api.ts and switch the export in lib/data/index.ts.
  2. Invite → join → profile → submitInvites, drafts with autosave, and server-side checks on submit (lib/profile/validate.ts).
  3. Owners review, and the emailsReview queue, approve, suggest edits and the waitlist invite, with emails through the outbox.
  4. Public profiles and photos/p/[slug] for approved Gigsters, with photo storage on R2.
  5. Launch: switch the public funnel to 2.0Deploy the "Make live" routes to between-gigs.com, keeping /api/professionals3 and /api/sketches.

Done when: the whole journey works on between-gigs.com with real emails, owner routes return 403 for Gigsters, no secrets are in the front-end bundle, and none of the internal routes respond. The full list is in the backend handoff.
